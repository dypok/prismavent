# Development Summary – Edit Event Resource

## Overview

During the development of this user story, the **Event Resource Editing** module was implemented, allowing authenticated users to update the information of resources associated with an event through an intuitive inline editing experience. The solution integrated Frontend and Backend functionalities to provide a seamless workflow, including validations, dynamic data updates, and automatic budget synchronization after every modification.

---

# Frontend

The user interface was developed to allow users to edit event resources directly from the Event Details page.

## Implemented Features

- Implemented edit and delete icons that become visible when hovering over each resource card.
- Developed an inline editing mode that replaces the resource card content with editable input fields.
- Automatically pre-filled the form with the existing resource information when editing begins.
- Implemented actions to save or cancel changes directly from the interface.
- Added keyboard shortcuts:
  - **Enter** to save changes.
  - **Escape** to cancel editing.
- Automatically updated the resource card after a successful edit.
- Dynamically recalculated the event budget after every modification.
- Instantly refreshed the totals displayed in the budget panel without reloading the page.

---

# Backend

The server-side logic was implemented to support partial updates of resources associated with an event.

## Implemented Endpoint

### PATCH /events/{event_id}/items/{item_id}

Developed the endpoint responsible for updating an existing event resource.

The implementation includes:

- Validation that the event exists.
- Verification of event ownership using the authenticated user.
- Validation that the requested resource exists.
- Verification that the resource belongs to the specified event.
- Partial updates using only the fields provided in the request.
- Automatic preservation of existing values for fields not included in the update.

---

# Validations

Both Frontend and Backend validations were implemented to ensure data integrity.

## Frontend

During editing, users can:

- Modify only the necessary fields.
- Cancel editing without affecting the stored information.
- Save changes using either the interface buttons or keyboard shortcuts.

## Backend

A validation schema was implemented for partial resource updates, including:

- `name` as an optional field with a minimum length of one character.
- `quantity` as an optional integer greater than or equal to **1**.
- `unit_price` as an optional decimal value greater than or equal to **0**.
- `notes` as an optional field with a maximum length of **300 characters**.

---

# Data Processing

Additional logic was implemented to keep the event information synchronized after every update.

These features include:

- Dynamic update of the edited resource card.
- Automatic recalculation of the estimated budget.
- Refreshing the totals displayed in the budget panel.
- Immediate synchronization of the interface with the Backend.
- Preserving existing values whenever a field is not modified.

---

# API Integration

The communication between the Frontend and Backend was completed for the event resource editing module.

The implementation includes:

- Integration of the **PATCH /events/{event_id}/items/{item_id}** endpoint.
- API consumption for updating existing resources.
- Automatic interface synchronization after every modification.
- Immediate budget updates without requiring a page reload.

---

# Final Outcome

As a result of this user story, the complete **Event Resource Editing** module was successfully implemented by integrating the Frontend and Backend to provide fast and efficient management of event resources.

The implemented solution allows users to:

- Edit the information of any resource directly from its corresponding card.
- Save or cancel changes using either buttons or keyboard shortcuts.
- Instantly view modifications without reloading the page.
- Keep the estimated event budget automatically updated after every change.
- Manage event resources through a dynamic, secure interface fully synchronized with the Backend.

The functionality was fully integrated between the Frontend and Backend, delivering a scalable, secure solution aligned with the project's architecture, ready for **Code Review** and **QA testing**.

# Resumen de Desarrollo – Editar Recurso del Evento

## Descripción General

Durante el desarrollo de esta historia de usuario se implementó el módulo de **Edición de Recursos del Evento**, permitiendo que los usuarios autenticados modifiquen la información de los recursos asociados a un evento de forma rápida e intuitiva mediante edición inline. La solución integró funcionalidades de Frontend y Backend para ofrecer una experiencia fluida, con validaciones, actualización dinámica de la información y sincronización automática del presupuesto del evento después de cada modificación.

---

# Frontend

Se desarrolló la interfaz necesaria para editar los recursos directamente desde la vista de detalle del evento.

## Funcionalidades implementadas

- Implementación de íconos de edición y eliminación visibles al pasar el cursor sobre cada tarjeta de recurso.
- Desarrollo de un modo de edición inline que reemplaza la información de la tarjeta por campos editables.
- Precarga automática de los datos existentes del recurso al iniciar la edición.
- Implementación de acciones para guardar o cancelar los cambios desde la interfaz.
- Soporte para atajos de teclado:
  - **Enter** para guardar los cambios.
  - **Escape** para cancelar la edición.
- Actualización automática de la tarjeta una vez finaliza la edición.
- Recalculo dinámico del presupuesto del evento después de cada modificación.
- Actualización inmediata de los totales mostrados en el panel de presupuesto sin necesidad de recargar la página.

---

# Backend

Se implementó la lógica necesaria para soportar la actualización parcial de los recursos asociados a un evento.

## Endpoint implementado

### PATCH /events/{event_id}/items/{item_id}

Se desarrolló el endpoint encargado de actualizar la información de un recurso existente.

La implementación incluye:

- Validación de la existencia del evento.
- Verificación de propiedad del evento mediante el usuario autenticado.
- Validación de la existencia del recurso solicitado.
- Verificación de que el recurso pertenezca al evento especificado.
- Actualización parcial de los datos utilizando únicamente los campos enviados en la solicitud.
- Conservación automática de los valores no modificados.

---

# Validaciones

Se implementaron validaciones tanto en el Frontend como en el Backend para garantizar la integridad de la información.

## Frontend

Durante la edición se permite:

- Modificar únicamente los campos necesarios.
- Cancelar la edición sin afectar la información almacenada.
- Guardar los cambios desde la interfaz o mediante atajos de teclado.

## Backend

Se implementó un esquema de validación para la actualización parcial de recursos que incluye:

- `name` como campo opcional con un mínimo de un carácter.
- `quantity` como entero opcional mayor o igual a **1**.
- `unit_price` como valor decimal opcional mayor o igual a **0**.
- `notes` como campo opcional con una longitud máxima de **300 caracteres**.

---

# Procesamiento de Datos

Se incorporó lógica adicional para mantener sincronizada la información del evento después de cada actualización.

Estas funcionalidades incluyen:

- Actualización dinámica de la tarjeta editada.
- Recalculo automático del presupuesto estimado.
- Actualización de los totales mostrados en el panel de presupuesto.
- Sincronización inmediata de la interfaz con la información almacenada en el Backend.
- Conservación de los valores existentes cuando un campo no es modificado.

---

# Integración de la API

Se completó la comunicación entre Frontend y Backend para la edición de recursos del evento.

La implementación incluye:

- Integración del endpoint **PATCH /events/{event_id}/items/{item_id}**.
- Consumo de la API para actualizar recursos existentes.
- Sincronización automática de la interfaz después de cada modificación.
- Actualización inmediata del presupuesto sin necesidad de recargar la página.

---

Como resultado de esta historia de usuario se implementó el módulo completo para la **Edición de Recursos del Evento**, integrando Frontend y Backend para ofrecer una administración rápida y eficiente de los recursos asociados a cada evento.

La solución permite que el usuario pueda:
