# Development Summary – Mark Event Resource as Confirmed

## Overview

During the development of this user story, the **Resource Confirmation** module was implemented, allowing users to manage the confirmation status of each event resource through an interactive and intuitive interface. The solution integrated Frontend and Backend functionalities to update the confirmation status in real time while automatically synchronizing the event budget and progress indicators.

---

# Frontend

The user interface was developed to allow users to manage the confirmation status of event resources directly from the Event Details page.

## Implemented Features

- Implemented a toggle switch to confirm or unconfirm event resources.
- Added visual differentiation between confirmed and pending resources using custom styles.
- Developed a reusable graphical component to display the percentage of the budget used.
- Automatically updated the budget panel after changing a resource's confirmation status.
- Instantly synchronized the confirmed resources counter.
- Dynamically updated the event progress indicator.
- Replaced emoji-based icons with SVG icons consistent with the application's design system.

---

# Backend

The server-side logic was implemented to support updates to a resource's confirmation status.

## Resource Update

The resource update schema was extended to allow dynamic modification of the confirmation status.

The implementation includes:

- Addition of the optional `confirmed` field to the update schema.
- Automatic update of the confirmation status whenever the client sends this field.
- Reuse of the existing resource update workflow without affecting the remaining business logic.

---

# Validations

Several validations were implemented to ensure data integrity and security.

These include:

- Verification of event ownership using the authenticated user.
- Prevention of modifications to resources belonging to other users.
- Updating only the fields included in the request.

---

# Data Processing

Additional logic was implemented to keep all event information synchronized.

These features include:

- Immediate update of the resource confirmation status.
- Automatic recalculation of the used budget.
- Dynamic update of the budget usage percentage.
- Synchronization of the confirmed resources counter.
- Refresh of the event progress indicator without requiring a page reload.

---

# API Integration

The communication between the Frontend and Backend was completed for resource confirmation management.

The implementation includes:

- Integration of the resource update endpoint.
- Sending the `confirmed` status from the user interface.
- Automatic synchronization of the budget and visual indicators after every update.
- Preservation of the Single Page Application (SPA) experience without page reloads.

---

# User Experience Improvements

In addition to the core functionality, several visual enhancements were implemented to improve resource status visibility.

These include:

- Visual differentiation between confirmed and pending resources.
- Animated graphical indicator representing the percentage of the budget used.
- Instant updates across all related interface components.
- SVG iconography consistent with the application's design system.

---

# Final Outcome

As a result of this user story, the complete **Resource Confirmation** module was successfully implemented by integrating Frontend and Backend to provide a dynamic, intuitive, and responsive user experience.

The implemented solution allows users to:

- Confirm or unconfirm event resources.
- Easily identify the status of each resource through visual indicators.
- View the percentage of the budget used in real time.
- Keep the budget, event progress, and confirmed resources counter synchronized.
- Manage event resources through an interface fully integrated with the Backend without requiring page reloads.

The functionality was fully integrated between the Frontend and Backend, delivering a scalable, consistent solution aligned with the project's architecture, ready for **Code Review** and **QA testing**.

# Resumen de Desarrollo – Marcar Recurso como Confirmado

## Descripción General

Durante el desarrollo de esta historia de usuario se implementó el módulo para **marcar recursos como confirmados**, permitiendo que los usuarios gestionen el estado de cada recurso del evento de manera visual e interactiva. La solución integró funcionalidades de Frontend y Backend para actualizar el estado de confirmación en tiempo real, mejorar la representación visual de los recursos y sincronizar automáticamente el progreso del presupuesto y los indicadores del evento.

---

# Frontend

Se desarrolló la interfaz necesaria para gestionar el estado de confirmación de los recursos directamente desde la vista de detalle del evento.

## Funcionalidades implementadas

- Implementación de un interruptor (toggle) para confirmar o desconfirmar recursos.
- Diferenciación visual entre recursos confirmados y pendientes mediante estilos personalizados.
- Creación de un indicador gráfico reutilizable para mostrar el porcentaje del presupuesto utilizado.
- Actualización automática del panel de presupuesto después de modificar el estado de un recurso.
- Sincronización inmediata del contador de recursos confirmados.
- Actualización dinámica del indicador de progreso del evento.
- Sustitución de iconografía basada en emojis por iconos SVG consistentes con el sistema de diseño.

---

# Backend

Se implementó la lógica necesaria para soportar la actualización del estado de confirmación de los recursos.

## Actualización del recurso

Se amplió el esquema de actualización de recursos para permitir modificar dinámicamente el estado de confirmación.

La implementación incluye:

- Incorporación del campo opcional `confirmed` en el esquema de actualización.
- Actualización automática del estado cuando el cliente envía dicho campo.
- Reutilización del flujo de actualización existente sin afectar el resto de la lógica del recurso.

---

# Validaciones

Se implementaron validaciones para garantizar la seguridad e integridad de la información.

Estas incluyen:

- Verificación de propiedad del evento mediante el usuario autenticado.
- Restricción para impedir modificaciones sobre recursos pertenecientes a otros usuarios.
- Actualización únicamente de los campos enviados en la solicitud.

---

# Procesamiento de Datos

Se incorporó lógica adicional para mantener sincronizada toda la información del evento.

Estas funcionalidades incluyen:

- Actualización inmediata del estado de confirmación de los recursos.
- Recalculo automático del presupuesto utilizado.
- Actualización del porcentaje de utilización del presupuesto.
- Sincronización del contador de recursos confirmados.
- Actualización del indicador de progreso del evento sin necesidad de recargar la página.

---

# Integración de la API

Se completó la comunicación entre Frontend y Backend para la gestión del estado de confirmación de los recursos.

La implementación incluye:

- Integración del endpoint de actualización de recursos.
- Envío del estado `confirmed` desde la interfaz.
- Sincronización automática del presupuesto y los indicadores visuales después de cada actualización.
- Conservación de la experiencia SPA sin recargas de página.

---

# Mejoras de Experiencia de Usuario

Además de la funcionalidad principal, se realizaron mejoras visuales para facilitar la interpretación del estado de los recursos.

Estas incluyen:

- Diferenciación visual entre recursos confirmados y pendientes.

# Resultado Final

Como resultado de esta historia de usuario se implementó el módulo completo para **marcar recursos como confirmados**, integrando Frontend y Backend para ofrecer una experiencia dinámica, visual e intuitiva.
