# Development Summary – Add Resource to an Event

## Overview

During the development of this user story, the **Event Resource Management** module was implemented, allowing authenticated users to add, edit, and delete resources associated with an event dynamically. The solution integrated Frontend and Backend functionalities to provide a fully interactive experience, including client-side and server-side validations, automatic budget updates, and real-time synchronization with the data stored in the database.

---

# Frontend

The user interface was developed to manage event resources directly from the event details page.

## Implemented Features

- Implemented the **"+ Add Resource"** card at the end of the resource list following the established design.
- Developed an inline form to register new resources without using modals or page redirections.
- Implemented client-side validation before sending data to the Backend.
- Dynamically updated the resource list after adding a new resource without reloading the page.
- Automatically recalculated the budget panel after every modification.
- Updated the confirmed resources counter.
- Implemented inline editing of resources by reusing the same creation form.
- Implemented resource deletion with a confirmation dialog.
- Automatically refreshed the interface after creating, editing, or deleting a resource.
- Displayed an empty state whenever the event has no associated resources.

---

# Backend

The server-side logic was implemented to support the creation of new resources associated with an event.

## Implemented Endpoint

### POST /events/{event_id}/items

Developed the endpoint responsible for creating a new resource within an event.

The implementation includes:

- Validation that the event exists.
- Verification of event ownership using the authenticated user.
- Automatic initialization of the `confirmed` field as **False** for every newly created resource.
- Safe persistence of the resource within a database transaction.
- Returning the created resource to keep the Frontend synchronized.

---

# Validations

Both Frontend and Backend validations were implemented to ensure data integrity.

## Frontend

Before submitting data to the server, the application validates that:

- The resource name is not empty.
- The quantity is greater than or equal to **1**.
- The unit price is a valid numeric value.

## Backend

A validation schema was implemented for event resources, including:

- `name` as a required field.
- `quantity` as an integer greater than or equal to **1**.
- `unit_price` as a decimal value greater than or equal to **0**.
- `notes` as an optional field with a maximum length of **300 characters**.

---

# Data Processing

Additional logic was implemented to keep the event information synchronized after every modification.

These features include:

- Dynamic insertion of newly created resource cards.
- Replacing the empty state when the first resource is added.
- Automatic budget panel updates.
- Recalculation of the estimated budget.
- Updating the remaining budget with visual indicators based on the available balance.
- Updating the confirmed resources counter.
- Editing and deleting resources without reloading the page.

---

# API Integration

The communication between the Frontend and Backend was completed for the event resource management module.

The implementation includes:

- Integration of the **POST /events/{event_id}/items** endpoint.
- API consumption for creating resources.
- Integration of resource update and deletion operations.
- Automatic interface synchronization after every operation.

---

# Final Outcome

As a result of this user story, the complete **Event Resource Management** module was successfully implemented by integrating Frontend and Backend to provide dynamic management of the resources associated with each event.

The implemented solution allows users to:

- Add new resources directly from the event details page.
- Edit the information of any existing resource.
- Delete resources with confirmation.
- Validate information before submitting it to the server.
- Instantly view changes without reloading the page.
- Keep the estimated budget and the event's financial status automatically updated.
- Manage all event resources through a dynamic, secure interface fully synchronized with the Backend.

The functionality was fully integrated between the Frontend and Backend, delivering a scalable, secure solution aligned with the project's architecture, ready for **Code Review** and **QA testing**.

# Resumen de Desarrollo – Añadir Recurso al Evento

## Descripción General

Durante el desarrollo de esta historia de usuario se implementó el módulo de **Gestión de Recursos del Evento**, permitiendo que los usuarios autenticados puedan agregar, editar y eliminar recursos asociados a un evento de manera dinámica. La solución integró funcionalidades de Frontend y Backend para ofrecer una experiencia completamente interactiva, con validaciones en cliente y servidor, actualización automática del presupuesto y sincronización en tiempo real con la información almacenada en la base de datos.

---

# Frontend

Se desarrolló la interfaz necesaria para administrar los recursos del evento directamente desde la vista de detalle.

## Funcionalidades implementadas

- Implementación de la tarjeta **"+ Añadir Recurso"** al final del listado de recursos siguiendo el diseño establecido.
- Desarrollo de un formulario inline para registrar nuevos recursos sin utilizar modales ni redirecciones.
- Validación de los datos ingresados antes de enviarlos al Backend.
- Actualización dinámica del listado de recursos al agregar un nuevo elemento sin necesidad de recargar la página.
- Recalculo automático del panel de presupuesto después de cada modificación.
- Actualización del contador de recursos confirmados.
- Implementación de edición inline de recursos reutilizando el mismo formulario de creación.
- Implementación de eliminación de recursos con confirmación previa.
- Actualización automática de la interfaz después de crear, editar o eliminar un recurso.
- Visualización del estado vacío cuando no existen recursos asociados al evento.

---

# Backend

Se implementó la lógica necesaria para soportar el registro de nuevos recursos asociados a un evento.

## Endpoint implementado

### POST /events/{event_id}/items

Se desarrolló el endpoint encargado de registrar un nuevo recurso dentro de un evento.

La implementación incluye:

- Validación de la existencia del evento.
- Verificación de propiedad del evento mediante el usuario autenticado.
- Inicialización automática del estado `confirmed` en **False** para todos los recursos nuevos.
- Persistencia del recurso dentro de una transacción segura.
- Retorno del recurso creado para sincronizar la interfaz del usuario.

---

# Validaciones

Se implementaron validaciones tanto en el Frontend como en el Backend para garantizar la integridad de la información.

## Frontend

Antes de enviar la información al servidor se valida que:

- El nombre del recurso no esté vacío.
- La cantidad sea mayor o igual a **1**.
- El precio unitario sea un valor numérico válido.

## Backend

Se creó un esquema de validación para los recursos que incluye:

- `name` como campo obligatorio.
- `quantity` como entero mayor o igual a **1**.
- `unit_price` como valor decimal mayor o igual a **0**.
- `notes` como campo opcional con una longitud máxima de **300 caracteres**.

---

# Procesamiento de Datos

Se implementó lógica adicional para mantener actualizada la información del evento después de cada modificación.

Estas funcionalidades incluyen:

- Inserción dinámica de nuevas tarjetas de recursos.
- Reemplazo del estado vacío cuando se agrega el primer recurso.
- Actualización automática del panel de presupuesto.
- Recalculo del presupuesto estimado.
- Actualización del saldo disponible con indicadores visuales según el presupuesto restante.
- Actualización del contador de recursos confirmados.
- Edición y eliminación de recursos sin recargar la página.

---

# Integración de la API

Se completó la comunicación entre Frontend y Backend para la gestión de recursos del evento.

La implementación incluye:

- Integración del endpoint **POST /events/{event_id}/items**.
- Consumo de la API para crear recursos.
- Integración de las operaciones de actualización y eliminación de recursos.
- Sincronización automática de la interfaz después de cada operación.

---

# Resultado Final

Como resultado de esta historia de usuario se implementó el módulo completo para la **Gestión de Recursos del Evento**, integrando Frontend y Backend para ofrecer una administración dinámica de los recursos asociados a cada evento.

La solución permite que el usuario pueda:

La funcionalidad quedó completamente integrada entre Frontend y Backend, proporcionando una solución escalable, segura y alineada con la arquitectura del proyecto, lista para el proceso de **Code Review** y pruebas de **QA**.
