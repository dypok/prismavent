# Development Summary – Optional Guest Management by Name

## Overview

During the development of this user story, the **Guest Management** module was implemented, allowing authenticated users to manage the guests associated with an event through create, read, update, and delete operations. The solution integrated Frontend, Backend, and Database functionalities to provide a complete guest management experience, including capacity validation, automatic synchronization with the Backend, and real-time guest statistics, ensuring a smooth and consistent user experience.

---

# Frontend

The user interface was developed to manage guests from both the event details page and a dedicated guest management view.

## Implemented Features

- Implemented the guest panel within the event details page, displaying the first guests and providing access to the complete guest list.
- Developed a dedicated guest management page featuring:
  - Search by guest name and notes.
  - Status filters (All, Confirmed, and Pending).
  - Sorting by alphabetical order, status, and creation date.
  - Pagination.
  - Guest statistics.
- Implemented a reusable modal for creating and editing guests.
- Integrated the following guest management operations:
  - Create guest.
  - Edit guest.
  - Delete guest.
- Added a confirmation dialog when the number of registered guests exceeds the expected guest capacity (`guest_count`).
- Automatically synchronized the interface after every operation without requiring a page refresh.
- Implemented **Skeleton Loaders** while guest information is being retrieved.
- Improved error handling by displaying user-friendly messages whenever communication with the Backend fails.

---

# Backend

The server-side logic was implemented to support complete guest management for each event.

## Implemented Endpoints

The complete guest management module was implemented through the following endpoints:

- **GET /events/{id}/guests**
- **POST /events/{id}/guests**
- **PATCH /events/{id}/guests/{guest_id}**
- **DELETE /events/{id}/guests/{guest_id}**

The implementation includes:

- Authenticated user validation.
- Event ownership verification.
- Event status validation before allowing modifications.
- Secure execution of all guest CRUD operations.

---

# Database

The data model was extended to support guest management.

## Implemented Components

A new **Guest** model and the **guests** table were created, linked to the **events** table through a foreign key with **ON DELETE CASCADE**.

Additionally, the required schemas were implemented to:

- Create guests.
- Update guests.
- Return guest information.
- Include guests and their statistics within the event details response.

---

# Data Processing

Additional logic was implemented to maintain data consistency for guest management.

These features include:

- Automatic synchronization of the `guest_count` field whenever the number of registered guests exceeds the originally planned capacity.
- Dynamic calculation of:
  - Total registered guests.
  - Confirmed guests.
  - Pending guests.
- Automatic updating of the guest counters displayed within the event details page.

---

# API Integration

The communication between the Frontend and Backend was completed for the guest management module.

The implementation includes:

- Integration of all guest management endpoints.
- CRUD operations consumed from the Frontend.
- Automatic interface updates after every modification.
- Compatibility of the **PATCH /events** endpoint with the new guest management logic.

---

# Validations

Several validations were implemented to ensure data integrity.

These include:

- Event ownership verification.
- Authentication-based access control.
- Restricting modifications on completed events.
- User confirmation whenever the number of guests exceeds the expected capacity.
- Consistency validation between the planned guest count and the actual number of registered guests.

---

# Final Outcome

As a result of this user story, the complete **Optional Guest Management by Name** module was successfully implemented by integrating Frontend, Backend, and Database components to provide efficient guest administration for every event.

The implemented solution allows users to:

- View the list of guests associated with an event.
- Search, filter, sort, and paginate guest information.
- Create, edit, and delete guests.
- View updated statistics for registered, confirmed, and pending guests.
- Keep the event information synchronized with the actual number of registered guests.
- Manage guests through a dynamic, secure interface fully synchronized with the Backend.

The functionality was fully integrated between the Frontend and Backend, delivering a scalable, secure solution aligned with the project's architecture, ready for **Code Review** and **QA testing**.

# Resumen de Desarrollo – Gestión Opcional de Invitados por Nombre

## Descripción General

Durante el desarrollo de esta historia de usuario se implementó el módulo de **Gestión de Invitados**, permitiendo que los usuarios autenticados administren los invitados asociados a un evento mediante operaciones de creación, consulta, edición y eliminación. La solución integró funcionalidades de Frontend, Backend y Base de Datos para ofrecer una gestión completa de invitados, incluyendo validaciones de capacidad, sincronización automática con el Backend y estadísticas actualizadas en tiempo real, garantizando una experiencia de usuario fluida y consistente.

---

# Frontend

Se desarrolló la interfaz necesaria para administrar los invitados desde el detalle del evento y desde una vista dedicada.

## Funcionalidades implementadas

- Implementación del panel de invitados dentro del detalle del evento mostrando los primeros registros y acceso a la lista completa.
- Desarrollo de una página dedicada para la gestión de invitados con:
  - Búsqueda por nombre y notas.
  - Filtros por estado (Todos, Confirmados y Pendientes).
  - Ordenamiento alfabético, por estado y por fecha de creación.
  - Paginación.
  - Estadísticas de invitados.
- Implementación de un modal reutilizable para crear y editar invitados.
- Integración de las operaciones de:
  - Crear invitado.
  - Editar invitado.
  - Eliminar invitado.
- Validación visual que solicita confirmación cuando el número de invitados supera el cupo previsto (`guest_count`).
- Sincronización automática de la información después de cada operación sin necesidad de recargar la página.
- Implementación de indicadores de carga mediante *Skeleton Loaders* mientras se consulta la información.
- Mejoras en el manejo de errores para mostrar mensajes amigables cuando ocurre un fallo en la comunicación con el Backend.

---

# Backend

Se implementó la lógica necesaria para soportar la gestión completa de invitados asociados a un evento.

## Endpoints implementados

Se desarrolló el módulo completo de invitados mediante los siguientes endpoints:

- **GET /events/{id}/guests**
- **POST /events/{id}/guests**
- **PATCH /events/{id}/guests/{guest_id}**
- **DELETE /events/{id}/guests/{guest_id}**

La implementación incluye:

- Validación del usuario autenticado.
- Verificación de propiedad del evento.
- Validación del estado del evento antes de permitir modificaciones.
- Gestión segura de todas las operaciones CRUD sobre invitados.

---

# Base de Datos

Se amplió el modelo de datos para soportar la administración de invitados.

## Componentes implementados

Se creó el modelo **Guest** y la tabla **guests**, relacionada con la tabla **events** mediante una clave foránea con eliminación en cascada (**ON DELETE CASCADE**).

Además, se implementaron los esquemas necesarios para:

- Crear invitados.
- Actualizar invitados.
- Retornar la información de invitados.
- Incluir los invitados y sus estadísticas dentro del detalle del evento.

---

# Procesamiento de Datos

Se incorporó lógica adicional para mantener la consistencia de la información relacionada con los invitados.

Estas funcionalidades incluyen:

- Sincronización automática del campo `guest_count` cuando el número de invitados registrados supera el cupo inicialmente definido.
- Cálculo dinámico de:
  - Total de invitados registrados.
  - Invitados confirmados.
  - Invitados pendientes.
- Actualización automática de los contadores mostrados en el detalle del evento.

---

# Integración de la API

Se completó la comunicación entre Frontend y Backend para el módulo de invitados.

La implementación incluye:

- Integración de los endpoints de gestión de invitados.
- Consumo de la API desde el Frontend mediante operaciones CRUD.
- Actualización automática de la interfaz después de cada modificación.
- Compatibilidad del endpoint de actualización de eventos (`PATCH /events`) con la nueva lógica de invitados.

---

# Validaciones

Durante el desarrollo se implementaron diversas validaciones para garantizar la integridad de la información.

Estas incluyen:

- Verificación de propiedad del evento.
- Control de acceso mediante autenticación.
- Restricción de modificaciones sobre eventos finalizados.
- Confirmación del usuario cuando el número de invitados supera el cupo previsto.

Como resultado de esta historia de usuario se implementó el módulo completo de **Gestión Opcional de Invitados por Nombre**, integrando Frontend, Backend y Base de Datos para ofrecer una administración eficiente de los asistentes de cada evento.
