# Resumen de Desarrollo – Cambiar el Estado de un Evento

## Descripción General

Durante el desarrollo de esta historia de usuario se implementó el flujo completo para la gestión del estado de un evento, permitiendo que los usuarios autenticados puedan avanzar el estado de sus eventos siguiendo un flujo controlado de negocio. La solución integró funcionalidades de Frontend y Backend para sincronizar la interfaz con la lógica del servidor, validar transiciones permitidas, proteger eventos finalizados y registrar automáticamente el historial de cambios de estado, garantizando la integridad de la información y una experiencia de usuario consistente.

---

# Frontend

Se desarrolló la interfaz necesaria para permitir el cambio de estado de un evento desde la vista de detalle.

## Funcionalidades implementadas

- Implementación del botón para avanzar el estado del evento desde el panel de detalle.
- Integración con el endpoint **PATCH /events/{id}/status** para actualizar el estado del evento.
- Actualización dinámica del texto del botón según el siguiente estado disponible:
  - **Confirm Event** cuando el evento se encuentra en estado **Borrador**.
  - **Finish Event** cuando el evento se encuentra en estado **Confirmado**.
- Ocultamiento automático del botón cuando el evento alcanza el estado **Finalizado**.
- Sincronización automática del **Stepper** visual después de cada cambio de estado sin necesidad de recargar la página.
- Implementación de indicadores visuales del estado del evento en la vista **My Events** mediante badges diferenciados por color.
- Reemplazo del botón **Editar** por un botón deshabilitado **Finalizado** cuando el evento ya no admite modificaciones.
- Implementación de un banner informativo en la vista de detalle indicando que los eventos finalizados no pueden modificarse.

---

# Backend

Se fortaleció la lógica del servidor para garantizar transiciones válidas entre estados y proteger la integridad del flujo de negocio.

## Endpoint implementado

### PATCH /events/{id}/status

Se actualizó el endpoint encargado de modificar el estado de un evento.

La implementación incluye:

- Validación del usuario autenticado.
- Verificación de propiedad del evento.
- Validación de que el evento no se encuentre finalizado antes de permitir modificaciones.
- Actualización del estado únicamente cuando la transición es válida.

---

# Reglas de Negocio

Se implementó una validación centralizada para controlar todas las transiciones de estado.

Las reglas incluyen:

- Definición de una secuencia oficial de estados:

  - **Borrador**
  - **Confirmado**
  - **Finalizado**

- Permitir únicamente avanzar al siguiente estado de la secuencia.
- Rechazar:
  - Saltos de estado.
  - Retrocesos.
  - Estados inexistentes.
  - Intentos de avanzar un evento ya finalizado.

---

# Seguridad y Validaciones

Se extendieron las validaciones para impedir modificaciones sobre eventos finalizados.

Estas protecciones fueron aplicadas en los siguientes endpoints:

- `PATCH /events/{id}`
- `PATCH /events/{id}/status`
- `POST /events/{id}/guests`
- `PATCH /events/{id}/guests/{id}`
- `DELETE /events/{id}/guests/{id}`

Con estas validaciones se garantiza que ningún recurso asociado pueda modificarse una vez el evento alcanza su estado final.

---

# Historial de Cambios

Se implementó un sistema automático de auditoría para registrar todas las transiciones de estado.

## Componentes implementados

Se creó la tabla **event_history**, encargada de almacenar:

- Evento asociado.
- Estado anterior.
- Nuevo estado.
- Usuario que realizó el cambio.
- Fecha y hora del cambio.

Además, se desarrolló la lógica necesaria para registrar automáticamente cada transición de estado dentro de la misma transacción utilizada para actualizar el evento, garantizando consistencia e integridad de los datos.

---

# Pruebas

Se incorporaron nuevas pruebas unitarias e integrales para validar el correcto funcionamiento de la funcionalidad.

Estas pruebas verifican:

- Transiciones válidas.
- Saltos de estado.
- Retrocesos.
- Estados inválidos.
- Intentos de modificar eventos finalizados.
- Registro automático del historial de cambios.
- Ciclo completo de transición **Borrador → Confirmado → Finalizado**.

---

# Resultado Final

Como resultado de esta historia de usuario se implementó el flujo completo para el cambio de estado de un evento, integrando Frontend y Backend bajo reglas de negocio centralizadas.

La solución permite que el usuario pueda:

- Avanzar el estado de un evento desde la interfaz.
- Visualizar dinámicamente la siguiente acción disponible.
- Observar el progreso actualizado mediante el Stepper visual.
- Consultar indicadores visuales del estado del evento.
- Evitar modificaciones sobre eventos finalizados.
- Garantizar que únicamente se ejecuten transiciones válidas entre estados.
- Registrar automáticamente un historial de auditoría por cada cambio realizado.

La funcionalidad quedó completamente integrada entre Frontend y Backend, proporcionando una solución segura, escalable y alineada con la arquitectura del proyecto, lista para el proceso de **Code Review** y pruebas de **QA**..

# Development Summary – Change Event Status

## Overview

During the development of this user story, the complete event status management workflow was implemented, allowing authenticated users to advance the status of their events through a controlled business process. The solution integrated Frontend and Backend functionalities to synchronize the user interface with the server-side logic, validate allowed state transitions, protect completed events from further modifications, and automatically record every status change in an audit history, ensuring data integrity and a consistent user experience.

---

# Frontend

The user interface was enhanced to allow users to update an event's status directly from the event details page.

## Implemented Features

- Implemented the button to advance the event status from the event details panel.
- Integrated the **PATCH /events/{id}/status** endpoint to update the event status.
- Dynamically updated the button label according to the next available status:
  - **Confirm Event** when the event is in **Draft** status.
  - **Finish Event** when the event is in **Confirmed** status.
- Automatically hid the button when the event reaches the **Completed** status.
- Synchronized the visual **Stepper** after every status change without requiring a page refresh.
- Added visual status badges in the **My Events** view to represent each event state.
- Replaced the **Edit** button with a disabled **Completed** button when the event can no longer be modified.
- Displayed an informational banner in the event details page indicating that completed events cannot be edited.

---

# Backend

The server-side logic was enhanced to guarantee valid state transitions and preserve the integrity of the event lifecycle.

## Implemented Endpoint

### PATCH /events/{id}/status

The endpoint responsible for updating an event's status was enhanced.

The implementation includes:

- Authentication validation.
- Event ownership verification.
- Validation that completed events cannot be modified.
- Status updates only when the requested transition is valid.

---

# Business Rules

A centralized validation mechanism was implemented to control every event status transition.

The implemented rules include:

- Definition of the official event lifecycle:

  - **Draft**
  - **Confirmed**
  - **Completed**

- Allowing only transitions to the immediate next status.
- Rejecting:
  - Status skipping.
  - Status rollback.
  - Invalid or unknown statuses.
  - Attempts to advance an event that has already been completed.

---

# Security and Validations

Additional validations were implemented to prevent modifications to completed events.

These protections were applied to the following endpoints:

- `PATCH /events/{id}`
- `PATCH /events/{id}/status`
- `POST /events/{id}/guests`
- `PATCH /events/{id}/guests/{id}`
- `DELETE /events/{id}/guests/{id}`

These validations ensure that no event-related resources can be modified after the event reaches its final state.

---

# Audit History

An automatic audit mechanism was implemented to record every event status transition.

## Implemented Components

A new **event_history** table was created to store:

- Associated event.
- Previous status.
- New status.
- User who performed the change.
- Date and time of the change.

Additionally, the logic was implemented to automatically register every status transition within the same database transaction used to update the event, guaranteeing consistency and atomicity.

---

# Testing

New unit and integration tests were added to validate the functionality.

These tests verify:

- Valid status transitions.
- Status skipping.
- Status rollback.
- Invalid status values.
- Attempts to modify completed events.
- Automatic creation of audit history records.
- The complete lifecycle transition **Draft → Confirmed → Completed**.

---

# Final Outcome

As a result of this user story, the complete event status management workflow was successfully implemented by integrating both Frontend and Backend under centralized business rules.

The solution allows users to:

- Advance an event's status directly from the user interface.
- Dynamically view the next available action.
- See the updated progress through the visual Stepper.
- View visual indicators representing the current event status.
- Prevent modifications to completed events.
- Ensure that only valid status transitions are executed.
- Automatically generate an audit history for every status change.

The functionality was fully integrated between the Frontend and Backend, delivering a secure, scalable solution aligned with the project's architecture, ready for **Code Review** and **QA testing**.
