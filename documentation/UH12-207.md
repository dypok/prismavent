# Development Summary – View Automatic Estimated Budget

## Overview

During the development of this user story, the **Automatic Estimated Budget** module was consolidated, allowing the estimated cost of an event to be calculated and displayed in real time based on its registered resources. The solution integrated Frontend and Backend functionalities to ensure that the estimated budget, over-budget alerts, and budget overrun amount remain synchronized after any modification made to the event resources.

---

# Frontend

The previously implemented budget panel was validated to ensure it continued to meet all the functional requirements of this user story.

## Implemented Features

- Dynamic visualization of the event's estimated budget.
- Automatic budget updates after any modification to event resources.
- Display of alerts whenever the estimated budget exceeds the configured limit.
- Currency formatting using the COP monetary format.
- Automatic refresh of the budget panel without requiring a page reload.

---

# Backend

The server-side logic was centralized to provide a single source of truth for all budget-related calculations.

## Implemented Services

A centralized budget service was developed to:

- Calculate the estimated budget using all resources associated with the event.
- Automatically detect when the estimated budget exceeds the maximum allowed budget.
- Calculate the exact budget overrun amount whenever applicable.

---

## Updated Endpoint

### GET /events/{id}

The endpoint was refactored to return the complete event details with dynamically calculated financial information.

The response includes:

- Estimated budget (`total_estimated`).
- Budget alert indicator (`budget_alert`).
- Exact budget overrun amount (`amount_over_budget`).
- Event resources and guests.

---

# Automatic Recalculation

Automatic budget recalculation was implemented after every modification to the event resources.

These operations include:

- Creating resources.
- Updating resources.
- Deleting resources.

After each operation, the Backend returns the complete updated event with all financial information recalculated.

---

# API Integration

The communication between the Frontend and Backend was completed to keep the event budget synchronized.

The implementation includes:

- Integration of the **GET /events/{id}** endpoint with dynamic calculations.
- Reuse of the centralized budget service.
- Automatic return of the updated event after every resource CRUD operation.
- Immediate synchronization of the user interface with the calculated Backend data.

---

# Validations

Business rules were implemented to ensure the accuracy of financial calculations.

These include:

- Budget calculations using `Decimal` for financial precision.
- Automatic detection when the estimated budget exceeds the configured limit.
- Accurate calculation of the budget overrun amount.
- Elimination of duplicate calculations by using a single source of truth for the estimated budget.

---

# Testing

Integration tests were updated to validate:

- The new endpoint response contract.
- Correct estimated budget calculations.
- Accurate budget overrun calculations.
- Automatic updates after every CRUD operation.

The entire test suite completed successfully, ensuring the stability of the implemented functionality.

---

# Final Outcome

As a result of this user story, the **Automatic Estimated Budget** module was fully consolidated by integrating Frontend and Backend to provide accurate, real-time financial calculations.

The implemented solution allows users to:

- Automatically view the estimated budget of an event.
- Immediately identify when the budget exceeds the configured limit.
- See the exact budget overrun amount.
- Receive updated financial information after every modification to event resources.
- Keep the user interface fully synchronized with the Backend without reloading the page.

The functionality was fully integrated between the Frontend and Backend, delivering a scalable, consistent solution aligned with the project's architecture, ready for **Code Review** and **QA testing**.

# Resumen de Desarrollo – Ver Presupuesto Estimado Automático

## Descripción General

Durante el desarrollo de esta historia de usuario se consolidó el módulo de **Presupuesto Estimado Automático**, permitiendo calcular y visualizar en tiempo real el costo estimado de un evento a partir de los recursos registrados. La solución integró funcionalidades de Frontend y Backend para garantizar que el presupuesto, las alertas por sobrecostos y el excedente sobre el presupuesto máximo permanezcan siempre sincronizados después de cualquier modificación realizada sobre los recursos del evento.

---

# Frontend

Se verificó la correcta integración del panel de presupuesto previamente implementado, asegurando que continuara cumpliendo los criterios funcionales definidos para esta historia de usuario.

## Funcionalidades implementadas

- Visualización dinámica del presupuesto estimado del evento.
- Actualización automática del presupuesto después de cualquier modificación en los recursos.
- Visualización de alertas cuando el presupuesto supera el límite definido.
- Formateo de los valores monetarios utilizando el formato de moneda COP.
- Actualización automática del panel de presupuesto sin necesidad de recargar la página.

---

# Backend

Se implementó la lógica centralizada para calcular el presupuesto del evento y mantener una única fuente de verdad para todos los procesos relacionados.

## Servicios implementados

Se desarrolló un servicio central de presupuesto encargado de:

- Calcular el presupuesto estimado utilizando todos los recursos asociados al evento.
- Detectar automáticamente cuando el presupuesto supera el valor máximo permitido.
- Calcular el monto exacto del excedente cuando existe sobrepresupuesto.

---

## Endpoint actualizado

### GET /events/{id}

El endpoint fue refactorizado para devolver el detalle completo del evento con la información financiera calculada dinámicamente.

La respuesta incluye:

- Presupuesto estimado (`total_estimated`).
- Indicador de sobrepresupuesto (`budget_alert`).
- Valor exacto del excedente (`amount_over_budget`).
- Recursos e invitados asociados al evento.

---

# Recalculo Automático

Se implementó la actualización automática del presupuesto después de cualquier modificación realizada sobre los recursos del evento.

Estas operaciones incluyen:

- Creación de recursos.
- Edición de recursos.
- Eliminación de recursos.

Después de cada operación, el Backend devuelve el estado completo del evento con toda la información recalculada.

---

# Integración de la API

Se completó la comunicación entre Frontend y Backend para mantener sincronizado el presupuesto del evento.

La implementación incluye:

- Integración del endpoint **GET /events/{id}** con cálculo dinámico.
- Reutilización del servicio centralizado de presupuesto.
- Respuesta automática del evento actualizado después de cada operación CRUD sobre los recursos.
- Sincronización inmediata de la interfaz con la información calculada por el Backend.

---

# Validaciones

Se implementaron reglas de negocio para garantizar la precisión de la información financiera.

Estas incluyen:

- Cálculo del presupuesto utilizando operaciones con precisión decimal (`Decimal`).
- Detección automática cuando el presupuesto supera el límite configurado.
- Cálculo exacto del monto excedido respecto al presupuesto máximo.
- Eliminación de cálculos duplicados mediante una única fuente de verdad para el presupuesto.

---

# Pruebas

Se actualizaron las pruebas de integración para validar:

- El nuevo contrato de respuesta del endpoint.
- El cálculo correcto del presupuesto estimado.

La totalidad de las pruebas del módulo fue ejecutada exitosamente, garantizando la estabilidad de la funcionalidad.
