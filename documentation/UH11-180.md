# Development Summary – Delete Event Resource

## Overview

During the development of this user story, the **Event Resource Deletion** module was implemented, allowing authenticated users to safely and intuitively remove resources associated with an event. The solution integrated Frontend and Backend functionalities to provide a user experience consistent with the application's design system, including a custom confirmation modal, visual interface improvements, and security validations before performing the deletion.

---

# Frontend

The user interface was enhanced to provide a more consistent and user-friendly resource deletion workflow.

## Implemented Features

- Replaced the delete emoji with a reusable SVG icon consistent with the application's design system.
- Implemented a custom confirmation modal to replace the browser's native confirmation dialog.
- Integrated the confirmation modal into the Event Details page.
- Allowed users to confirm or cancel the deletion directly from the interface.
- Preserved the dynamic interface update after a resource is deleted.

---

# Backend

The server-side logic was implemented to support the secure deletion of resources associated with an event.

## Implemented Endpoint

### DELETE /events/{event_id}/items/{item_id}

Developed the endpoint responsible for deleting a resource belonging to an event.

The implementation includes:

- Validation that the event exists.
- Verification of event ownership using the authenticated user.
- Validation that the requested resource exists.
- Verification that the resource belongs to the specified event.
- Secure deletion of the resource after all validations pass.
- Returning a success message after completing the operation.

---

# Validations

Several validations were implemented to ensure data integrity and security.

These include:

- Event existence validation.
- Event ownership verification.
- Resource existence validation.
- Verification that the resource belongs to the specified event.
- Explicit user confirmation before performing the deletion.

---

# API Integration

The communication between the Frontend and Backend was completed for the resource deletion workflow.

The implementation includes:

- Integration of the **DELETE /events/{event_id}/items/{item_id}** endpoint.
- API consumption through the confirmation modal.
- Automatic interface updates after a resource is deleted.
- Preserving the Single Page Application (SPA) experience without requiring a page reload.

---

# User Experience Improvements

In addition to the core functionality, several visual improvements were implemented to maintain consistency across the application.

These include:

- SVG icons aligned with the application's design system.
- A confirmation modal matching the style used for event deletion.
- A more intuitive and consistent confirmation flow compared to the browser's native dialog.

---

# Final Outcome

As a result of this user story, the complete **Event Resource Deletion** module was successfully implemented by integrating Frontend and Backend to provide a secure, consistent, and user-friendly deletion process.

The implemented solution allows users to:

- Delete resources associated with an event.
- Confirm or cancel the operation through a custom confirmation modal.
- Interact with a user interface consistent with the rest of the application.
- Ensure that only the event owner can delete event resources.
- Keep the interface synchronized with the Backend without reloading the page.

The functionality was fully integrated between the Frontend and Backend, delivering a scalable, secure solution aligned with the project's architecture, ready for **Code Review** and **QA testing**.

# Resumen de Desarrollo – Eliminar Recurso del Evento

## Descripción General

Durante el desarrollo de esta historia de usuario se implementó el módulo para la **eliminación de recursos del evento**, permitiendo que los usuarios autenticados eliminen recursos asociados a un evento de forma segura e intuitiva. La solución integró funcionalidades de Frontend y Backend para ofrecer una experiencia consistente con el diseño del sistema, incorporando un modal de confirmación personalizado, mejoras visuales en la interfaz y validaciones de seguridad antes de ejecutar la eliminación.

---

# Frontend

Se mejoró la interfaz de usuario para ofrecer un flujo de eliminación más consistente y alineado con el diseño de la aplicación.

## Funcionalidades implementadas

- Reemplazo del emoji de eliminación por un icono SVG reutilizable y consistente con el sistema de diseño.
- Implementación de un modal de confirmación para eliminar recursos, sustituyendo el diálogo nativo del navegador.
- Integración del modal con la vista de detalle del evento.
- Confirmación o cancelación de la eliminación desde la interfaz sin alterar el flujo existente.
- Conservación de la actualización dinámica de la vista tras eliminar un recurso.

---

# Backend

Se implementó la lógica necesaria para soportar la eliminación segura de recursos asociados a un evento.

## Endpoint implementado

### DELETE /events/{event_id}/items/{item_id}

Se desarrolló el endpoint encargado de eliminar un recurso perteneciente a un evento.

La implementación incluye:

- Validación de la existencia del evento.
- Verificación de propiedad del evento mediante el usuario autenticado.
- Validación de la existencia del recurso solicitado.
- Verificación de que el recurso pertenezca al evento especificado.
- Eliminación segura del recurso una vez superadas todas las validaciones.
- Retorno de un mensaje de éxito después de completar la operación.
